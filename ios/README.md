# MotoNav iOS 0.16.0

面向 iPhone 的圆屏导航 App，最低 iOS 15。本次为 build6：界面参考 coolcoolmanman-design/MotoNav 的 0.15.21-tpms，使用导航、轨迹、圆屏、我的四个栏目，系统蓝强调色、自动深浅色、玻璃导航栏、设备卡和连接动画。0.16.0 原有导航功能继续保留。日常界面不展示调试日志、传输统计、帧率、SDK 参数或测试按钮。

## 本次更新

- 蓝牙连接、配对验证后同步手机时间和时区，供圆屏显示 24 小时时间；重连、时区或系统时间改变时重新同步。
- 摩托车规划历史保存完整起点、终点和有序途经点，最多保留 20 条。再次使用会重新规划，避免使用过期路线。
- 途经点支持添加、替换、上移、下移、删除和搜索附近加油站，最多三个；点击应用后统一重新规划，取消不改路线。
- 地点选择可使用收藏和最近目的地，历史路线可删除或按出行类型清空。
- 导入高德分享链接遇到登录或验证时，可打开正常验证页面后重试。会话只保存在本机，不绕过验证码。
- 模拟速度统一为 60 / 100 / 120 km/h。
- 连接状态显示圆屏名称和上报的电量；支持从列表切换圆屏，以及确认后让圆屏忘掉其他手机。
- 手机导航地图减少反复重建路线和标记，只在路线改变时更新路线覆盖层。
- 保留地图风格、巡航、语音、轨迹、音乐控制、和风天气实况与逐小时、分钟降水、空气质量、天气预警等既有功能。

## 配置和安装

交付 IPA 未签名，需要自行签名后安装。签名工具必须保留并签名 MotoNavShare 分享扩展。重新签名可能改变 Bundle ID；申请高德 iOS Key 时，填写安装后 App 配置页实际显示的 Bundle ID。

在 App 的地图 Key 栏目填写自己的高德 iOS Key。和风天气为可选配置，填写自己的 API Host 和 API Key，启用分钟降水、空气质量、天气预报、天气预警四类 API。本源码和安装包不内置作者的账号、个人 Key、API Host 或签名证书。

圆屏需要与所用板型匹配的 MotoNav 固件。App 在 iPhone 设置中获得蓝牙和定位权限后连接圆屏，并按圆屏提示完成配对。锁屏前等待沿线地图下载完成。

## 平台差异和验证范围

本版不接入红绿灯倒计时。iOS 后台不允许持续进行 GPU 地图截图，因此后台依靠提前准备的沿线底图；偏离已下载范围时可能需要回到 App 补图。定位、语音和蓝牙后台能力仍受系统权限、用户强制关闭 App 和系统调度影响，不能保证永久后台运行。

普通驾车 SDK 导航保留其提供的车道引导；摩托车网页路线未获得与安卓车机相同的实时车道数据，不能伪造为已对齐。iOS 不开放与安卓相同的来电号码读取、接听控制和所有第三方播放器能力，音乐信息与控制以播放器和圆屏支持情况为准。

构建会检查路线、偏航与到达、BLE 传输、时间同步、历史记录、分享 Cookie 隔离和地图处理逻辑。编译成功不代表已经完成 iPhone 锁屏和实际道路测试；需在自己的 iPhone 与圆屏组合上验证。

## 从源码构建

需要 Mac、Xcode 和 CocoaPods 1.16.2。在本目录运行 `pod _1.16.2_ install --deployment`，打开 MotoNav.xcworkspace 编译。项目使用 Podfile.lock 锁定的高德 SDK。

上级目录的 build-ios.sh 可在 Mac 上构建未签名 arm64 IPA。用户服务配置在手机本地填写，不要将个人配置提交到公开仓库。


## Build2 界面与高速底图修正

四栏目与分组设置、轨迹地图缩略及详情、圆屏设备卡、连接动画和导航转向卡已适配。iOS 26 使用系统玻璃，旧系统或旧 Xcode 构建回退至系统材质。连接动画只在可用蓝牙下启动，配对验证通过后显示成功，超时可关闭；无调试和测试帧入口。

界面参考来源与改动范围见 UI-SOURCE-NOTICE.md。本版没有移植参考版的胎压、音乐封面或新增固件协议，保留现有 0.16.0 协议和功能；无需仅为此次 UI 更新刷固件。

针对“前台亮屏、高速时路线和车头仍在但底图空白”，修正了 0.16.0 固定亮度阈值漏识别灰色高速路的问题。底图改用实测背景亮度，拒绝近乎空白的新图和缓存覆盖，保留已有有效地图。60 km/h 及以上暂缓额外楼块截图，优先道路与底图传输，已缓存楼块仍能显示；低速恢复补充。沿线底图应在出发前保持前台准备。

灰色道路提取、空白包拒绝、缓存保留以及 60/80/100/120 km/h 的地图覆盖切换均设回归检查。它们验证代码行为，不能替代实体 iPhone 和圆屏的高速实路测试；此次修正不代表已复现并彻底消除使用者在其他分支版本中的所有空白现象。


## Build3 自行车规划与黑纹修正

针对“自行车路线缺少分段”：请求骑行扩展信息，优先解析真实分段；没有分段坐标时读取完整路径坐标。保留真实路线，不以起终点直线代替；坐标缺失、异常或跳跃仍会拒绝。只有路线轨迹时，会提示暂无分段转向指引，按地图沿线引导，不生成虚构的转弯位置和语音。

针对 Build2 灰色楼块被误当成黑色道路：撤销仅凭颜色差将所有灰色区域归类为道路的判断，灰色道路恢复改为保守的长条形状检查，排除小楼块及网状纹理。规则属于图像识别，不能保证保留所有灰色街巷。白色、彩色道路及真实楼块图层保持原有处理；取图视图固定浅色，避免手机外观改变分类底色。罪恶都市底图使用新的缓存目录，更新后重新准备沿线路线，旧黑纹缓存不再读取。

本次保持 iOS 0.16.0，内部构建号为 3；针对反馈中的 7.12.10-pages.4 保持现有传输格式，先更新 App，无需仅为此修正换固件。仍需自己的 iPhone 和圆屏验证真实骑行规划及相同地点的地图效果；合成图像检查不能替代现场复测。


## Build3 待机时钟与 QQ 音乐歌名

pages.4 的待机主页显示 --:-- 表示尚未收到有效手机时间。本版校时使用有应答的蓝牙写入，与地图写入串行，避免超过默认 20 字节上限或同时占用写应答；在连接初期追加两次新鲜时间重发；已认证通道的能力消息可补足漏收的 U,1 通知，回到 App 也会重新校时。“圆屏 → 连接管理 → 校准圆屏时间”可手动重发。使用固件相同的 2020–2099 年、UTC 偏移不超过 14 小时范围；不将旧时间加入重连缓存。时钟仍在骑手待机主页显示，本次不增加导航地图页的时钟。

QQ 音乐继续使用系统蓝牙媒体按键与 AMS 歌曲信息。增加有次数限制的信息重取，修复缺失片段后不再更新的问题；歌名/歌手位图按实际蓝牙容量缩小或截短，避免超过 32 包直接丢弃。按键控制可用不代表系统已经提供歌名；本次不会改用 Apple Music 读取 QQ 音乐。时钟与歌名在本人 iPhone/圆屏组合上的真实结果仍需复测。


## Build4 风格切换与网纹样本

用户实测：罪恶都市关闭楼块后仍有黑网；高德原版真正开始模拟后黑网消失；极简仍出现灰色网纹，龙珠不出现。此前 Build3 的合成检查没有复现真实纹理，不能据此声称网纹已修复。

本次修正明确的风格切换问题：使用 pages.4 的独立风格命令，撤销旧底图传输与重发状态，切换后按当前位置主动准备新图；校验缓存包符合所选风格，避免把罪恶都市的图仅换色后当作原版或极简。时钟与路线传输不因清理底图被取消。高德原版取图开启 SDK 原生建筑显示并更新该风格缓存；建筑能否显示仍由 SDK 当前缩放和可用图层决定，不伪造楼块。

在“圆屏 → 圆屏显示 → 地图显示问题：生成对照图”中，可在问题区域手动生成一次全新取图，查看和导出 01-source.png、02-converted.png、sample.json、map.bin。两张图片来自同一份基础底图，转换结果颜色为材质示意；它们用于确认真实纹理在原始图还是转换后产生。平时不记录图片，未开启诊断时不生成 PNG，也不会自动上传。导出含所处地图区域，未包含个人 Key、Cookie 或绝对 GPS 参考点。

此版不宣称已消除持续出现的黑网。需要真实对照图才能进一步修正处理规则；原版建筑显示与图像效果均未在该 iPhone/圆屏实机复测。


## Build5 浅色地块网纹修正

真实原始图与转换图确认，黑网已在手机基础底图分类阶段产生。地图里存在约 242 和 248 两种浅色地块，旧版“比主要底色亮 6 即是道路”的条件把后一种地块及其微小插值色差当成道路。现在白色道路对齐安卓固定 254/255 的接近纯白亮度条件，黄色道路、水面、绿地及保守灰色道路识别保留。

罪恶都市风格使用第 3 代缓存，不读取旧版错误转换结果；写入新图时清理前两代该风格缓存。升级后请在前台重新准备沿线路线，圆屏仍可使用 7.12.10-pages.4，不需要为此刷固件。原版和极简风格不增加本次分类规则。

主应用和分享扩展均为 0.16.0 build5。通过真实 JPEG 样本的离线回放与 Swift 颜色/整图处理回归；尚未在用户 iPhone 和圆屏上复测。诊断取样入口保留，用户提供的原始地图图片不收入公开源码。


## Build6 高速底图衔接与楼块准备顺序

针对最初版 0.16.0 在前台亮屏时高速底图接不上、楼块跟不上的反馈，本次修改调度，不更改圆屏协议或地图分辨率。沿线的“准备目标”与“显示目标”分开：按车速提前 12 秒沿真实路线取图，提前得到的新图先保留，覆盖当前视口且上一个蓝牙地图传输结束后才发送；准备中的前方图不再因为尚不能覆盖当前完整屏幕而被取消。旧地图保持到新图完整接收。此处的保留与接收均沿用固件原本行为，本次未修改固件。

附近几块基础地图准备好后，优先补即将经过区域的楼块，不再等待整条长路线全部基础图下载完成。有可用的近段基础图缓冲时，高速也允许离线任务补附近楼块；现场缺图时，楼块任务仍让位于基础地图。导航中的楼块交给沿线调度器，避免前台同一区域重复提取。补楼块复用同区域已有基础包，省去一次重复的远景截图与颜色分类。某一区域重试不再暂停所有区域下载。

包括 60/80/100/120 km/h、4 秒取图加 1 秒发送、8 秒取图加 3 秒发送的延迟模拟检查；旧版晚准备规则可复现空白，新规则在这些检查范围内覆盖连续。检查不包含任意网络断连或无限慢的蓝牙，不能保证任何速度和延迟下都没有空白。实际 SDK 取图、iPhone 发热和圆屏显示仍需实机测试。

本版保持 0.16.0，内部 build6，保留 Build3–5 的自行车、时间、音乐、清爽界面与黑网修正。现有 7.12.10-pages.4 无需为此刷写。更新后在前台重新规划并准备沿线底图；首次长路线仍应在出发前等待附近底图就绪。
