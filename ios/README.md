# MotoNav iOS v0.13.9

与 Android 共用本仓库 1.75 英寸圆屏固件及 BLE 协议。原始 iOS 工程来自用户提供的 MotoNav-iOS，整合后的源代码保存在此目录；原目录未修改。

预编译 IPA 安装请看 [Sideloadly 安装教程](../docs/INSTALL-IOS.md)。公开版本使用通用包名，地图 Key 按重签后的实际 Bundle ID 申请。

## 0.13.9 高德「行程报告」分享导入

导航结束后分享的「行程报告」链接、以及「我的足迹」里分享的路线，现在也能粘贴还原。短链跳到高德活动页（`?urlParameter=…`），页面本身不含路线数据；App 截取 `urlParameter` 调 `m5.amap.com/ws/share/lbs/info` 与 `route/restoration` 两个接口，按 `naviType` 自动识别驾车（2）或摩托车（9），沿用原有导航发图路径，不新增固件协议。详情见 [更新说明](../docs/RELEASE-IOS-0.13.9.md)。

“前方终点”图标继续作为正常导航发送，不再触发圆屏到达动画。只有当前导航真正到达，或当前模拟导航确实结束，才发送一次到达指令。手动退出先关闭回调入口，重复结束与旧会话回调会被忽略；旧的到达清理计时也不会清除新导航或巡航。

## 构建与安装

1. Mac 安装 Xcode 与 CocoaPods，在本目录执行 `pod install`（版本由 Podfile.lock 固定）。
2. 打开 `MotoNav.xcworkspace`，为 MotoNav 和 MotoNavShare 两个 target 选择自己的开发 Team。
3. 修改两个 target 的 Bundle Identifier，扩展使用主应用 ID 加 `.share`；高德 iOS Key 绑定主应用 ID。
4. 选择 iPhone 运行。共享 Scheme 的 Run 默认采用 Release 优化，以保证地图处理和高速换图性能；逐行调试时可临时改为 Debug，真机导航验收与日常安装使用 Release。Key 均在手机界面填写，不写入源码。天地图为可选底图配置。
5. 和风天气在首页“Key 设置 → 和风天气”输入账号 API Host 和 API Key。天气按查看触发，缓存十分钟，实况失败退避三十秒；详情保留来源、全部有效预警与接口不可用提示。
6. QQ 音乐等使用默认开启的“蓝牙媒体按键”：圆屏升级到 v7.9.0 HID 固件，在 iPhone 系统蓝牙设置配对；需要原 Apple Music App 控制时关闭此开关，再点击授权。详见 [HID 使用说明](../docs/BLE-HID.md)。

无需签名的编译检查（从仓库根目录）：

```sh
xcodebuild -workspace ios/MotoNav.xcworkspace -scheme MotoNav \
  -destination 'generic/platform=iOS' -configuration Release \
  -derivedDataPath /tmp/MotoNavDerived CODE_SIGNING_ALLOWED=NO build
```

高德二进制 SDK 的模拟器架构有限，优先使用通用 iOS 目标编译与 iPhone 实测。仓库不提交 Pods、开发 Team、证书或构建产物。

## 高德底图与离线地图

iOS v0.13.0 首次启动（包括旧版升级）会默认选择高德并启用“俯视建筑轮廓”；之后保留用户的手动选择。连接认证后主动发送 `#GB?` 查询圆屏建筑能力，最多三次查询；未收到确认时先显示普通底图，不向旧固件发送建筑标志。切换到卫星图仍需要天地图 Key；龙珠雷达停止底图下载。

选定路线后，手机在前台串行准备沿线地图，进度显示在圆屏设置中。高德建筑取图失败时，普通底图先保存和显示，未完成的建筑随后重试。改变来源、建筑开关、路线或收到新固件能力时取消旧任务，按新配置重新准备；结束导航/取消规划停止预下载，已保存地图保留。

地图包保存在 Application Support/route_maps，排除备份，容量上限 512 MB，剩余空间不足 32 MB 时明确报错。按来源、坐标原点和图层分别保存普通/建筑版本；每次读取检查尺寸、坐标、颜色编号与完整 RLE 数据，写入使用原子替换。跨 App 重启仍可复用，锁屏读取采用首次解锁后可访问的文件保护。

**与 Android 的主要差异是后台取图：iOS 后台不能继续执行 GPU 渲染任务。** [Apple 的后台 GPU 说明](https://developer.apple.com/documentation/metal/preparing-your-metal-app-to-run-in-the-background)规定后台暂停 GPU 使用。本实现进入后台取消取图，继续发送已经离线的地图包，回到前台再下载。出发前应等沿线下载完成；如果当前位置没有可用离线包，会保留原地图并显示错误，不保证离线算路或实时路况。

## 逐小时预报修复（0.10.1）

和风新版小时接口的 forecastTime 可以只包含小时和分钟，例如 `2026-10-17T16:00+08:00`、`2026-10-17T08:00Z`。[官方数据格式](https://dev.qweather.com/docs/api/weather/weather-hourly-forecast/)中有无秒示例。原 iOS 直接用默认 ISO8601DateFormatter 解析，导致这些记录被全部丢弃，手机发送 H,0，圆屏显示实况但没有小时预报。0.10.1 兼容分钟、秒和小数秒时间，保留原时区；同时修复预警到期时间的同类解析问题。

手机天气摘要现在显示逐小时条数，接口失败显示 HTTP 状态，空列表或无效数据有明确说明。手动“刷新天气”跳过十分钟缓存；没有有效逐小时数据时只缓存三十秒。换配置或请求失败会清除 BLE 的旧天气缓存，重连不会重新显示旧数据。

圆屏 7.9.1 在 H,0 时显示 HOURLY UNAVAILABLE / CHECK PHONE WEATHER DETAILS，不生成虚构预报。此次恢复小时预报的关键是更新 iPhone App；只升级圆屏不能修复旧 App 的解析问题。

```sh

  ios/MotoNav/QWeatherForecast.swift ios/tests/weather/main.swift -o /tmp/motonav-weather-tests

```

### iOS v0.13.5 地图分片接收与换图优先级

固件 RX 环形队列共有 48 个槽，实际最多容纳 47 个待处理消息，满时丢弃最旧消息；每轮主循环最多处理 30 个消息。iOS 原 pump 仅依据 CoreBluetooth canSendWriteWithoutResponse 连续写入，主机栈背压无法保证外设应用队列不溢出。地图约 30 KB 就有 60 多个分片，这与延长实测中回执延迟、同编号重传后立即确认的现象吻合，但此次没有外设丢包计数，不能把应用层溢出计数当作已测得。

全部导航通道写入共用节奏预算，每 20 毫秒最多 6 包；额度覆盖位置更新、图片、地图与蓝牙就绪回调，不能通过反复调用 pump 绕过。导航优先，每五个普通消息至少给待发地图一个发送机会，避免持续图片更新挤掉地图；系统 HID 媒体按键仍由圆屏与 iPhone 直接处理。

缓存底图送出后，同中心的截图底图不再打断尚未确认的地图传输；字节相同的重复地图保留编号和确认状态。地图未确认且分片已发完时两秒重传，路线/原路线仍沿用原重传规则。下一块已经覆盖屏幕时，尚在补建筑的任务提前让出取图器，先切下一块普通底图，不再等旧图只剩 50 米余量才取消。

新增 BLE 节奏测试模拟固件 47 包容量、每轮最多 30 包、80 毫秒处理间隔；连续 1000 个分片无溢出，峰值待处理 24 包，并测试持续导航队列下地图不会饿死。18 项蓝牙节奏检查通过，地图处理的 669 项检查此前通过；Release 签名构建、v0.13.5 安装和正常启动已完成，等待正常前台高速导航复测。固件未改动。


v0.13.5 延长实测：前段地图回执约 1.2 秒，继续最高档模拟后仍有十几秒的接收延迟；用户确认出现空白后过一会补上。只分批写入仍不足以解决长传输排队，未将此版本标为完成。

### iOS v0.13.6 地图逐片写入确认

圆屏 RX 同时支持 WRITE 和 WRITE_NR。地图/路线大包改用 withResponse，一次仅有一片在途，收到 ATT 写入回调才发送下一片；每片失败最多三次，地图替换后旧失败片不会重新插入，收到圆屏 K 后清除该编号尚未发送的重传分片。保留圆屏 K 作为完整地图实际解码接收确认，ATT 回调不等同于整图确认。

实时位置、转向与设置等短指令仍优先；文字图片在地图传输期间让出发送带宽，避免图像持续更新使地图传输拖延。共用每 20 毫秒六包的节奏上限；仅支持 WRITE_NR 的旧设备保留兼容路径。单片写入五秒无回调时重新建立导航连接；系统 HID 媒体控制不改动。诊断记录地图首片/末片的实际写入及 ATT 回调，可区分主机排队、ATT 延迟和整图 K 回执。

20 项队列/传输检查通过：逐片串行、失败片原字节重试、替换后的旧回调、三次失败上限、独立路线保留、K 先于 ATT 回调、旧 K 不清除新包、断线清理，以及持续图片与每秒 50 条位置/转向指令下的地图传输。60 个分片在 35 毫秒 ATT 响应模型下约 2.13 秒完成，期间处理 107 条导航指令。另有 15 项发送节奏检查通过。Release 签名构建通过，更新正在手机安装验证。
